# AI 教学、独立验收与跨窗口交接模板

版本：v2，2026-10-26。对应 26 周主线＋4—6 周机动，整体约 7—8 个月。

使用方式：新开任何 AI 对话时，提供《CV工程能力培养总方案》、从《26周每日任务表》复制的当前周任务，以及最近一次交接记录。无需提供全部历史聊天。下面模板复制后填写即可；新教师应遵循本版总方案，而不是另开一套课程或把旧计划叠加进来。

## 一、教学启动指令

```text
请按附件《CV工程能力培养总方案》和当前任务教我，使用中文。

我的起点：计算机视觉研究生，方向为自监督 DRGBT 追踪。学过导数、链式法则和 Attention 数学，但最初不会独立读写函数、类、训练循环；会搭环境、运行脚本、定位报错行和使用 Git。当前实际水平以本次交接记录为准，不能一直把我当零基础。

我的目标：能独立实现 CNN、残差网络、Transformer 和 ViT 的核心结构；能读懂相关陌生仓库关键路径、配置并验证复现；能把自己的模型／损失／训练想法实现并做可信实验。

每天学习约 3 小时，另外的科研时间不计入。必须先讲清原理和执行机制，再示例走读，再独立练习。全新概念不要让我先对着空白文件猜；学过的内容不要直接给作业答案。

本版共 26 周主线，最后四周分别做陌生仓库和个人改造；另留 4—6 周机动。我的当前工程版本是 V__。请沿用已通过的数据工具／训练底座／模型库，不另造一份互不关联的项目；官方仓库环境与来源单独记录。

当前任务：W__ D__，任务原文如下：
【粘贴当日任务及本周成果要求】

今日主项／可选项：
【粘贴；没有选修就写“无”】

现有资源和未完成待办：
【解释器、设备、数据／权重访问及必要的路径，不确定就说明】

最近交接记录：
【粘贴记录】

请先核对本课的直接前置知识，最多给 2—3 个短检查；已通过的不要反复教。若有阻塞性缺口，先补一个最小概念。

请分步上课，不要一次输出全课程：
1. 说明本课要解决什么问题，解释原理、变量、输入输出和执行顺序。
2. 给一个小而完整、不同于独立作业的例子。先让我预测结果／形状，再运行或核对。解释新出现的语法。
3. 给独立练习及一个小变化题，只说明接口、约束和验收证据，暂不提供答案。
4. 等我交代码后，先检查我实际写了什么，用证据指出错误；必要时给分级提示，不直接重写整份工程。
5. 结束时生成交接记录，标明独立程度、未通过点、代码入口和下一课。

教学时间参考：原理 40 分钟、示例 25、练习 65、调试 35、交接 15。超时可拆课。不要把当天的小任务升级为完整论文复现。

如果当天内容是项目实践，可以减少重复讲解、增加动手，但总预算仍为 180 分钟。不要把每日 3 小时默认为 4 小时；时间不够先去掉可选项，不删原理解释和独立验收。

W07 的 OSTrack 只是限时预览，W09—13 只看已学概念对应的小片段。环境或 GPU 未就绪时标明待运行，继续基础任务；不能因看到输出截图就判为本人已推理通过。W17—19 再正式阅读和复现。

本次如果有故障演练，请先限定在已学机制，按“现象→候选原因→区分原因的检查→修复→变化复查”推进。不必把某种曲线与唯一原因硬对应，也不要求新手先无依据卡两小时。

请将性能／部署／DDP／compile／BAT 移植视为按条件选修，不自行加入主项。核心模型实现、损失指标和可信实验优先。

如果我只说“懂了”，请让我解释或预测一个小例子再判断。不能仅凭我点头或程序能跑就判定掌握。

允许查官方文档。涉及库 API 或仓库具体位置时，请按我实际版本核实；不要编造文件、参数、运行结果和指标。不能运行时明确告诉我应由我运行并回传什么证据。

每课标出 1—2 个对应的官方文档或教材小节，便于核对和复习；不要额外布置一整门课程。每日任务表需要你教学展开，不能只复述任务名后让我自行实现。
```

## 二、调试求助指令

```text
这是练习，不是让你替我完成工程。请先帮我理解错误，再引导我修复。

任务与预期：
【我想做什么，期待的输出／形状】

实际行为：
【完整报错或错误结果，不只截最后一行】

最小相关代码和运行命令：
【粘贴】

已知变量：
【shape、dtype、device、路径、类型、关键值等】

我的解释与已做检查：
【粘贴，实在没有就写“不知道”】

请按顺序回答：
1. 将异常类型和关键信息翻译为我能理解的话。
2. 区分异常出现的位置和可能的根因，给出目前有证据支持的判断。
3. 先让我做一个能区分原因的检查，或给一个概念／定位提示。
4. 我回传结果后再推进；确实需要时给局部伪代码或最小示范。
5. 修复后让我解释原因，并用一个变化例子复查。

不要通过忽略异常、盲目改版本或删掉检查来掩盖问题。
```

## 三、独立验收出题指令

```text
请依据总方案为 W__／阶段__ 设计一次独立验收。

已学内容与前次成果：
【粘贴】

请只提供题目、允许资料、输入输出／接口、运行预算和验收标准，不提供解答、代码骨架答案或逐步实现路径。题目应覆盖本阶段关键能力，包含一个未在示例中直接做过的变化。

验收应区分“代码实现与独立程度”和“本任务指标”。只在明确数据、预算、协议与阈值含义后设数值门槛；不要要求所有 MNIST／CIFAR 任务达到统一精度，也不要要求创新改造必须涨点。

我会关闭 AI 生成、补全与聊天建议，可查官方文档并用调试器。先独立完成并封存代码、运行输出和解释，再请你批改。计算开销需要合理，模型实现考核不以大规模精度为标准。

请不要把看过示例后复写同一题当作迁移能力。阶段题可以跨天完成，不能为了限时而省掉必要验证。
```

## 四、验收批改指令

```text
请批改我已独立完成并封存的阶段作业。

题目、我的代码、运行输出和解释：
【粘贴或提供文件】

我使用的资料／提示：
【如实列出】

请依据总方案，从原理解释、独立实现、调试验证、实验判断、交付复现五维逐项评为 0—4 分，只评本阶段适用的维度，并引用具体证据。
3 分表示能独立完成、解释并验证；4 分还需未见变化题的证据。

先核对结果和逻辑，不要因代码写得像标准答案就给高分。没有运行证据的行为不能假装已验证；正确代码但我解释不清，也不能判全部通过。

请给：已通过点、关键缺口、最小补练任务、一个变化题。不要直接给完整修正答案。涉及数据泄漏、梯度断开、坐标／评估错误或不可追溯结果时，必须指出其对结论的影响。

检查资源与复现层级：R1 官方权重评估、R2 缩减训练、R3 按论文配方完整重训。缺少运行证据应标未完成，不能用推测分数补齐。BAT 与 OSTrack 有代码继承关系，不能把换到 BAT 自动视为已经验证异构代码体系迁移。

若程序未提升指标，仍需按实现和实验是否有效判断；不能把没提升等同于不会工程。
```
