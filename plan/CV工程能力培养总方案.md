# 面向 RGB／RGBT／自监督追踪研究的工程能力培养总方案

版本：v2，2026-10-26，整合项目实战训练。配套文件：《26周每日任务表》《AI教学与验收交接模板》。三份文件可独立交给其他 AI；开始上课时提供总方案、当前周任务和最近一次交接记录。本版替代原 24 周版本。

## 1. 起点、终点与时间

学习者是计算机视觉研究生，研究方向为自监督 DRGBT 目标追踪。读过相关论文，学过导数、链式法则和 Attention 的数学概念，但尚不能独立读写函数、类、训练循环或真实模型代码。能创建环境、安装依赖、运行脚本、定位报错行及使用 Git；需要补充报错解释和调试能力。每天可用 3 小时学习，另有 4 小时科研时间；本方案只占学习时间。教学顺序必须是原理说明、示例走读、独立动手、反馈验收。

最终目标是：对相关领域一个陌生且资料足够的开源仓库，能建立运行环境，追踪数据、模型、损失和评估的执行路径，配置并验证复现；能把自己的结构或训练想法转为代码，完成训练、对照和结果分析。

建议安排 **26 周主线＋4—6 周机动，整体约 7—8 个月**。主线每天 3 小时、每周 7 天，共 546 小时；第 7 天用于复习、验收或补欠账。按 30—32 周计算，含机动的主动学习预算约 630—672 小时。相比原版，增加的两周只用于毕业项目，使陌生仓库复现与个人改造各有两周，不把新工具继续堆进主线。此周期是教学估计，不是学习效果保证；按达标情况调整。若实际每周只能学 6 天，主线约需 31 周，再加机动时间。

长时间训练可以在课外后台运行，主动学习时间用于实现、检查和分析。GPU 资源、数据访问及论文完整重训所需时间另计；缺资源时保留明确标注的缩减实验，不能据此宣称已经完整复现论文。

阶段预期：第 6 周形成独立小模型训练能力；第 7 周做 OSTrack 小范围预览；第 13 周形成 CNN、残差块、Transformer 和小型 ViT 的实现能力；第 19 周完成一次有证据的 OSTrack 代码分析及复现练习；第 22 周完成自监督／多模态衔接；第 26 周完成独立迁移和个人改造考核。它们均以对应验收通过为前提。

## 2. “会写模型”的具体范围

允许使用 Python、NumPy、PyTorch 的基础算子、卷积层、线性层、归一化层、优化器和自动求导。应能自行编写模型类和前向过程，并完成以下实现：

- CNN：依据通道数、核大小、步幅、填充编写网络，预测并核对各层形状；用一次小规模循环实现理解卷积，再用框架算子训练。
- ResNet：独立写 BasicBlock、恒等捷径和投影捷径，组织小型残差网络；理解 Bottleneck，并能据结构说明实现。知道小图变体与标准 ImageNet 结构的区别。
- Transformer：使用矩阵乘法和基础层写缩放点积注意力、多头拆分与合并、MLP、残差、LayerNorm、Encoder Block；能处理掩码并说明其是否适合当前任务。
- ViT：实现 patch embedding、token 组织、位置编码、Encoder 堆叠和输出头；理解分辨率、patch 尺寸、token 数和位置编码的关系。
- 追踪模型：能处理模板与搜索区域，组织骨干网络、特征交互和定位头，解释预测坐标如何回到原图。

最终核心实现验收时，不以直接调用现成 ResNet、ViT 或完整 Transformer 层代替上述实现。可以查基础 API，不要求重写自动求导、CUDA 内核或框架本身。后续研究可以使用预训练骨干，但需要理解、检查和修改其接口。

## 3. 每天如何学习

| 环节 | 时间 | 必须留下的证据 |
|---|---:|---|
| 原理教学 | 40 分钟 | 用自己的话解释概念、输入输出及用途 |
| 示例走读 | 25 分钟 | 先预测值或形状，再运行验证 |
| 独立练习 | 65 分钟 | 关闭示例，写自己的代码及一个变化版本 |
| 调试反馈 | 35 分钟 | 记录错误含义、证据、修复和复查结果 |
| 回忆交接 | 15 分钟 | 完成当日记录，写出下次入口 |

时间可以前后浮动；每天以一个核心概念和一个能运行的小成果为主。复杂课题拆天完成，不将两天欠账压进一天。每周 D7 不引入大量新知识；阶段周的 D7 做阶段验收。

学新知识时可以增加讲解时间，项目日可以压缩重复讲解、增加独立实现；全天仍以 180 分钟为预算。每课必须有可检查的产物，复杂任务拆课，不能把“听明白”自动等同于“会写”。

教学时允许 AI 完整解释和给出不同于作业的示例。对全新概念先教学，学过的内容再独立尝试。练习中卡住约 10 分钟后，可以逐级请求：概念提示→定位问题→伪代码→局部示范。10 分钟是可调整的起始规则。

验收时关闭 AI 生成、补全和聊天建议，允许查官方文档及使用调试器。先封存自己的代码和说明，再由 AI 批改。若提前看了同一道题的答案，换题后验收；只重写记住的答案不能证明掌握。

科研时可继续使用 AI，但把不会解释的片段登记到知识缺口清单。科研产出的 AI 代码不直接计入独立验收。

收尾动作：有实质代码修改时做一次有意义的 Git 提交；没有代码修改则保存学习记录，不为打卡制造空提交。写三行日志“做了什么／卡在哪里／下次第一步”，每周归档一次配置、曲线和错误记录。推送远程仓库按自己的备份安排执行，不把公开发布当作验收条件。

### 4.1 连续项目：让前面的代码真正用于后面的任务

只维护一个个人练习工程，课程成果按版本逐步扩展。官方仓库保留独立环境和来源记录，不直接覆盖自己的工程；通过接口图理解相同职责如何由不同写法实现。

| 工程版本 | 周次 | 继承与增加的能力 |
|---|---|---|
| V0 数据工具 | W01—03 | 图片清单、标注读取、样本检查、命令行和调试记录 |
| V1 训练底座 | W04—06 | 复用样本处理，加入小数据分类、训练／验证、日志、checkpoint |
| V2 模型库 | W07—13 | 同一训练底座切换自写 CNN、ResNet、小型 ViT，保存相应配置 |
| V3 mini-tracker | W14—16 | Moving MNIST 风格移动目标、干扰目标、模板搜索、匹配与定位、序列评估 |
| V4 仓库对应图 | W17—19 | 将自己的数据／模型／训练／评估职责对应到 OSTrack，完成真实复现与改动 |
| V5 自监督与双模态 | W20—22 | 复用编码器、数据及日志，增加双视图、自监督目标、模态标记和融合 |
| V6 独立研究工程 | W23—26 | 迁移到陌生仓库，完成自己的小改造与可追溯实验 |

MNIST 和 CIFAR-10 可用可获得、规模相近的数据替换，必须记录样本数、划分、预处理和训练预算。小任务不设脱离预算的统一 99%／80% 门槛；除连通性检查外，重点验收实现、解释和变化题。移动数字双模态版本只作接口练习，不据此推断真实 RGB／热红外性能。

项目早期可以只有几份清楚的脚本。W06 开始按需要整理为 configs、data、models、engine、train／evaluate 和 tests 等职责；每次抽取一个实际复用部分。配置先用已学过的字典／JSON，YAML 后补。日志先本地文件与曲线，WandB 等工具按需选用。断言和小测试优先检查框转换、配对增强、数据样本以及模型形状／梯度等容易静默出错的地方；不为每个包装函数写形式化测试。

### 4.2 提前看真实代码，但不让环境问题占掉基础课

W06 末只阅读仓库目录和一段已经能理解的调用代码，限 30 分钟。W07 做一次预览，限 90 分钟：记录版本，找推理入口、模板／搜索输入和输出框，资源就绪则跑一段序列。此前没有准备好环境或权重时，可以查看已有运行输出并标记“待运行”，不声称推理通过；剩余准备放在资源清单，继续基础主线。

之后 W09 对照骨干中的模块职责，W10 对照注意力形状，W12—13 对照 patch、token 和参数键。每次只看与当周已学概念对应的一小段，不要求现在理解全部仓库。W17—19 再回到同一固定版本正式分析和验收。

W03 盘点解释器、CPU／GPU、显存、操作系统、存储、数据和权重访问，以及是否有服务器；不假设某个 conda 环境、显卡或账号已存在。W16 复查正式复现所需资源。先用一个小数据集走通链路，再准备必要的完整数据；不把同时下载所有追踪数据集作为入门要求。资源受限时继续 CPU 可做的基础、合成序列、源码与小实验，真实推理和完整重训的未完成项另列。

### 4.3 故障演练：先学机制，再学识别异常

每周在已有知识范围内安排一个故障；阶段验收再给未知变体。并非每个故障都会抛异常，先学习观察现象，再用检查排除原因。

| 时段 | 重点故障 | 必须检查的证据 |
|---|---|---|
| W01—03 | 类型、属性、键／索引、路径、参数与返回值 | 完整 traceback、调用栈、实际类型和值 |
| W04—06 | 维度／广播、dtype／device、忘清梯度／反传／更新、标签错误 | shape、grad、更新前后参数、损失与标签接口 |
| W07—09 | train／eval 混淆、学习率失当、归一化及数值异常 | 训练验证曲线、模式、梯度和统计量 |
| W10—13 | softmax 轴、转置／拆头、未注册参数、位置编码／权重尺寸 | 人工注意力例子、named_parameters、形状和加载报告 |
| W14—19 | 框坐标／裁剪不一致、真值泄漏、预处理与评估协议不匹配 | 画框、执行路径、逐序列结果和官方协议 |
| W20—26 | stop-gradient 错误、表示坍塌、伪缺失模态被读取、对照不公平 | 梯度路径、表征统计、模态可用性和实验配置 |

每次故障记录“现象→候选原因→能区分原因的检查→修复→变化例子复查”。不知道根因时可先查文档、请求概念提示；不要求初学者无依据硬耗两小时。

## 5. 各阶段验收

### A：W03 结束

输入一个包含图片和标注的小目录，独立实现：稳定排序、过滤、样本配对、异常提示、统计和 JSON／CSV 输出。能将工具拆成函数和类，解释参数、返回值、实例属性和执行入口。做一次改题，例如标注格式或目录结构发生变化。

修复至少 5 个事先未知的问题，覆盖路径、数据类型、索引／键、函数参数及对象属性。必须说清异常类型、触发行、上游错误值及修复依据。用断点逐步观察一次函数调用，而不只在末尾加 print。

交付：代码、运行命令、样例输入输出、调试记录和 README。可查语法，核心流程独立写出。

### B：W06 结束

独立实现 Dataset／DataLoader、小型 MLP、训练与验证循环、损失和指标统计、保存加载及训练恢复。理解 logits、标签、损失的形状；区分训练模式、评估模式和梯度开关。检查梯度及参数实际变化。

在一个设计为可拟合的 16—32 样本简单任务上，在课程提前约定的训练预算内拟合到约定阈值；可采用训练准确率至少 95% 作为该练习阈值。若失败，能检查标签、损失、参数更新和模式。这个数字只用于该小任务的连通性验收，不能用于判断真实研究模型是否合格。

保存重载后，在 eval 模式下对同一输入核对输出，在当前精度合理容差内一致；恢复 optimizer 状态及训练步数。解释 train／val／test 分工，避免同一数据参与训练和最终测试。

提供一个便于继续扩展的项目结构、运行配置和本地日志；累计完成“梯度没有清零／没有反传或更新／标签或张量接口错误”等故障演练，并解释其现象不一定相同。优化器状态用于恢复其动量或其他累积状态，未恢复不等于所有任务都必然出现 loss 跳变；若使用 scheduler、AMP 或其他有状态组件，也记录和恢复相关状态。

### C：W09 结束

依据结构文字而非整份示例，独立写 CNN、BasicBlock、投影捷径和小型 ResNet，解释 Bottleneck 结构。输入分辨率和通道数变化时，能预测形状并修复残差相加不匹配。检查参数注册，能说明 ModuleList 与普通列表的区别。

在固定数据划分和训练预算下完成一个受控实验，提前写出假设，保存基线和修改版的配置、曲线及结果。能解释学习率、batch size、权重衰减、归一化和数据增强的作用；不把它们混同。结果没有提升也可以通过，关键是实验有效且解释有证据。

### D：W13 结束

独立实现注意力、多头注意力、Encoder Block、patch embedding 和小型 ViT，不能只封装现成完整模型。逐步解释图像→patch→token→QKV→注意力→输出的形状和含义；解释缩放、softmax 轴、头数、归一化与残差。

用一个人工可核对的小输入验证注意力计算；在约定的小任务上训练连通。改变输入分辨率或 patch 尺寸，说明 token 数、位置编码和计算量如何变化。能加载相容的部分预训练权重，检查缺失键、意外键和尺寸冲突；不能用 strict=False 掩盖所有问题。

### E：W16 结束

独立完成模板与搜索区域构造、简单匹配或定位头、坐标还原、单序列推理和结果可视化。使用已知模板寻找目标，保持追踪任务的条件输入；单独定位一个固定类别的模型只能算前置练习。

实现 xywh／xyxy／cxcywh 的明确转换和 IoU；检查裁剪、缩放及归一化是否同步作用于标注。预测框不能在推理时使用当前帧真值；离线评估时可以读真值。

能解释中心误差、归一化中心误差、成功率曲线及 AUC 的定义。报告必须说明阈值、汇总方式、首帧和无效帧处理；学习版评估与官方协议有差异时标明，正式比较使用基准官方实现。不要把分类 accuracy 直接当成追踪评价。

理解 L1、IoU／GIoU 类回归目标及分类／热图目标的用途，在明确标签构造后选用；能够解释总损失各项的数值尺度、权重和梯度路径。对损失下降但追踪变差给出可检查的候选原因。

至少输出一次响应热图、叠框视频／GIF 和失败序列说明。测试集应含未用于训练或调参的轨迹及干扰配置。若使用高斯响应标签，明确其数值范围及所用损失接口；本方案默认逐位置二元 soft target 与 BCEWithLogitsLoss，小规模匹配练习不混用类别交叉熵接口。说明响应图、裁剪图与原图三个坐标系之间的映射，误差阈值必须标明在哪个坐标系。简单方案固定框尺寸的局限必须披露。

### F：W19 结束

以 OSTrack 为主练习，先定位最小执行路径，不通读所有文件。仓库版本以实际选用 commit 为准，教学 AI 应打开源码核实路径。

1. 记录 commit、环境、依赖、数据划分、预处理、配置、权重来源和运行命令。
2. 跑通官方权重的推理和评估，并追踪一帧的模板、搜索、骨干、预测头、解码和原图坐标。
3. 追踪一个训练 batch，从采样、变换、模型前向、标签与损失到 backward 和参数更新。
4. 从论文结构图、公式、配置到代码建立对应表，解释所读关键路径中的 Python 语法。
5. 完成小数据训练、保存和恢复；资源具备时执行官方规模训练配方。
6. 独立修改一个参数化模块或损失项，确认参数注册、梯度、权重保存及配置生效。

复现报告分三层标记：R1＝官方权重评估复现；R2＝缩减数据／预算下训练链路复现；R3＝按论文配方完整重训并核对指标。分别说明完成到哪层。使用官方权重跑测试不等于完成 R3。

复现数值容差应在运行前依据同一官方协议、数据、权重精度和已知波动确定。差异存在时检查来源；不随意指定所有论文都通用的“差一点也算复现”。

正式训练前做 smoke test：小数据、少量步数，核查训练→保存→恢复→评估；通过再扩大数据和预算。用结构、标注数量、可视化抽查和实际加载统计核对数据。记录吞吐与显存，发现资源瓶颈时才选择一个性能选修，不同时引入 AMP、DDP、compile 和新数据格式。SSH／tmux 在已有远程服务器时学习，服务器缺失不阻塞前面的基础阶段。

复现报告固定包含：版本与环境、协议与数据、配方与预算、复现层级、逐序列及汇总结果、差异假设与验证、未完成项、重新启动命令。自写 mini-tracker 与 OSTrack 的职责对应图是必交物，具体字段和参数名以所用 commit 为准。OTB／LaSOT 等成功率 AUC 与 GOT-10k 的 AO／SR 等协议分开核对，不能仅用“AUC／SR”泛称所有基准。

### G：W22 结束

自监督部分选一条方法作为实现练习，本方案默认使用小规模 SimSiam 风格任务。能说明两种视图、共享编码器、投影／预测头、相似度目标和 stop-gradient，核对梯度到底流向哪里。这里使用它理解训练机制，不把它当成所有自监督追踪方法的统一模板。

至少检查特征方差或相似度分布以及一个简单下游表现；只看自监督 loss 下降不足以证明表征有效。用同一拆分做随机初始化与自监督预训练的受控比较；监督式线性评估应与无标签预训练阶段清晰分开。分类表征实验是前置练习，还需说明追踪中的时序样本、定位约束和伪标签如何另外设计。

多模态部分实现 RGB／T 成对加载、共同几何变换、简单融合和显式模态可用标记；说明真实传感器可能需要配准，不能因图像尺寸相同就假定位置对齐。模拟模态缺失时不读取缺失模态；检查训练和推理接口一致性，并按可用模态分组分析结果。

### H：W26 结束

完成下文两个毕业项目，并保存不依赖 AI 的初次实现、运行记录和报告。AI 可在封存后审阅；发现问题后本人修复，再用未见过的变化任务复验。

W23—24 专门用于陌生仓库的环境、推理、训练、评估和复现报告；W25—26 用于个人设想的设计、实现、基线、消融及最终交付。W24 结束前只选定个人项目题目，不要求同时完成模块。两周也不能保证所有仓库完整重训，资源和调试超时使用机动周。

## 6. 最终验收：围绕用户要求的两件事

### 项目一：看懂代码并配置复现

选一个此前没有逐行学过、与视觉／追踪相关且材料充分的仓库。不要选另一个几乎完全复制教学项目的版本。先做 1—2 天勘查，产出环境和实验预算；再按需要用数天至两周完成配置与验证，长训练等待单独计。

比较仓库的实际数据接口、模型组织、训练入口和评估脚本，确定其与 OSTrack 有实质差异。BAT 适合作为 RGB-T 迁移与融合练习；其代码基于 ViPT，后者基于 OSTrack，因此不将 BAT 作为验证不同代码体系迁移能力的唯一选择。[BAT 官方说明](https://github.com/SparkTempest/BAT)、[ViPT 官方说明](https://github.com/jiawen-zhu/ViPT)

验收证据：

- 可以从干净环境照自己的说明建立项目，记录所有兼容性修改。
- 指出训练和测试入口、配置来源、数据格式、模型建造、损失计算和评估位置。
- 解释一个训练 batch 与一个推理样本的完整流向；标出关键形状、坐标单位和权重来源。
- 完成 R1、R2；R3 根据资源单列，不以 R2 冒充。资源充足时补齐 R3。
- 核对论文协议，解释结果差异并出具证据；主动查明标签泄漏、预处理和划分错误。
- 修改一个未在教程中直接做过的接口或小模块，检查它确实参与训练。

“看懂代码”的验收范围是能独立定位和解释相关关键路径，能查询陌生语法并继续追踪；不要求脱离文档记住整个仓库或所有第三方库。

### 项目二：把自己的想法构建为实验

选择一个边界明确的设想，例如融合模块、定位头、损失项或训练采样策略。先写假设、输入输出、预期影响、基线和失败判据，再实现。

必须交付：

1. 模型结构与各层形状，关键公式和数据依赖说明。
2. 可运行代码、参数注册和梯度检查、小样本拟合或合适的连通性检查。
3. 可追溯配置、checkpoint、日志和从零启动命令。
4. 同一评估协议下的基线与修改版，至少一个能隔离核心想法的消融。
5. 有限但有效的超参数比较，使用验证集作选择，测试集用于最终报告。
6. 小规模实验预算允许时做 3 个随机种子；完整训练预算不足则如实报告样本数和不确定性。
7. 效果、代价、失败案例和局限分析；说明哪些结论有证据、哪些仍待验证。

创新结果未提升也可以通过工程能力验收；可发表性另行判断。通过的核心是能独立实现、检查并产生可信实验。

### 共同硬性要求

核心实现和初次排错独立完成，可查资料；能解释自己的代码，并完成一个未见变化题。程序能运行但解释不清、参数没有更新、数据或评估协议有泄漏、结果无法追溯，都不能判为通过。

评分采用五维各 0—4 分：原理解释、独立实现、调试验证、实验判断、交付复现。0＝未完成；1＝主要依靠答案；2＝需要实质提示；3＝独立完成且能用证据解释；4＝能处理未见变体。阶段要求相关维度均达到 3，不用总分抵消某一项缺口。AI 批改只是反馈，运行证据和变化题表现才是依据。

## 7. 工程与实验能力如何贯穿

- Python：先掌握表达式、容器、函数、对象、模块与异常；后续结合仓库学习迭代器／生成器、推导式、解包、关键字参数、上下文管理器、类型提示、装饰器、继承和注册机制。遇到复杂写法先还原成简单写法，不追求语法炫技。
- IDE：从第一周练断点、单步进入／跳过、变量查看、调用栈、跳转定义和全局搜索。远程服务器与 SSH 在真实仓库阶段按需补；基础阶段 CPU 即可，CNN／ViT 及真实训练使用可获得的 GPU。
- 环境：项目分离、解释器核对、依赖记录、CPU／GPU 与版本兼容、数据和输出路径分离。旧仓库遵循经过核实的兼容环境，不机械安装所有最新版。Docker、分布式训练和性能优化放到确有需求时。
- Git：每周保存有意义的提交，练习分支、diff、回滚和冲突；不反复花时间复习已熟悉的基础命令。记录代码版本与实验配置的对应关系。
- 报错：覆盖文件与导入、类型／属性／键／索引、形状／dtype／device、梯度断开、in-place 修改、NaN 和 OOM。学习辨别抛出位置与根因位置；不能靠捕获所有异常后忽略来修复。
- 实验：先建立可用基线，再改变一个可解释因素。记录数据拆分、随机性、训练预算、配置和选择规则。单次提升不直接推出结构必然更优。
- 复现：固定种子有帮助，但不能保证跨硬件、版本与平台得到逐位相同结果，应同时记录环境和实际波动。[PyTorch 可复现性说明](https://docs.pytorch.org/docs/2.14/notes/randomness.html)

## 8. 材料怎么选

材料跟随任务使用，每次只查当前问题所需内容。总方案是学习主线，课程不是额外叠加的另一套任务。

每课由教师标出 1—2 个确实对应本课概念的官方文档或教材小节，先解释零基础缺口，再引导查阅。每日任务表是学习目标和产物目录，不能替代教学，也不应被扩展成同时通读多个教材。代码和运行证据与资料互相核对，不只依赖 AI 的口头判断。

| 材料 | 使用阶段和方式 |
|---|---|
| [Python 官方教程](https://docs.python.org/3/tutorial/)及[异常章节](https://docs.python.org/3/tutorial/errors.html) | A 阶段作为语法和报错参考；该教程假设已有编程基础，因此零基础概念由教师先解释 |
| [PyTorch Learn the Basics](https://docs.pytorch.org/tutorials/beginner/basics/intro.html) | B 阶段核对张量、数据、模型、自动求导、优化及保存加载 |
| [动手学深度学习](https://zh.d2l.ai/) | B—D 阶段选读线性网络、卷积、残差、注意力和 ViT；用自己的小项目实现 |
| [CS231n](https://cs231n.stanford.edu/) | B 阶段之后按需选读优化、反向传播、CNN 等；官方先修包含 Python 熟练度，不作为最初起点 |
| [ResNet 原论文](https://arxiv.org/abs/1512.03385) | C 阶段对照残差块和网络结构 |
| [ViT 原论文](https://arxiv.org/abs/2010.11929)及[D2L ViT 章节](https://d2l.ai/chapter_attention-mechanisms-and-transformers/vision-transformer.html) | D 阶段对照结构与实现 |
| [OSTrack 官方仓库](https://github.com/botaoye/OSTrack)、[模型](https://github.com/botaoye/OSTrack/blob/main/lib/models/ostrack/ostrack.py)、[训练损失](https://github.com/botaoye/OSTrack/blob/main/lib/train/actors/ostrack.py) | F 阶段定位模型输入输出及损失路径，具体位置按实际 commit 核实 |
| [SimSiam 原论文](https://arxiv.org/abs/2011.10566)和[官方代码](https://github.com/facebookresearch/simsiam) | G 阶段理解双视图、预测头及 stop-gradient，先做缩小实验 |

教学材料和论文结构不是完成标准；能够独立解释、实现、调试和验证才是标准。

## 9. 进度调整规则

每周 D7 检查交付物、变化题和提示依赖。通过才前进；轻微缺口用下周开头一节补，函数／类、张量、训练循环、坐标变换等关键缺口未通过则停留补练。连续两周大量超时，应减小单题规模、拆分教学，使用机动周，不能取消独立练习以追赶日历。

每四周做一次不看旧答案的迁移练习，观察是否能独立调用已有知识。每阶段保留一个能在较小预算下重新运行的成果；最终以项目和运行记录组成能力档案。

有余力时优先做当周变化题、修复未知故障和减少提示依赖，而不是提前堆新工具。每周复核“主项／可选项／未完成项”；本周超时先去掉可选项，不取消原理教学、独立实现和验收。机动周优先分配给基础缺口与 W23—26 项目收尾。

切换 AI 时使用配套交接模板。每次提供当前任务、已通过内容、真实代码、完整报错和卡点；要求新教师不重复整份访谈，也不擅自把小型训练任务升级为完整科研项目。

## 10. 工程选修：有需求再加入，不占基础主线

下列为独立选修，不要求全部完成。若插入主线，必须替换一个可选任务或另加时间，不能默认每日学习从 3 小时增加到 4 小时。参考周期只供估算，须按模型与硬件调整。

| 选修 | 开始条件 | 练习与产物 |
|---|---|---|
| P1 性能诊断，约 2—3 次课 | 单卡训练正确且已有可测瓶颈 | 测数据等待和计算时间，选择 num_workers／pin_memory 或 profiler 中一个问题，记录优化前后吞吐；不以“工具已接入”作结论 |
| P2 AMP，约 1—2 次课 | FP32 基线和可用 GPU 已就绪 | 核对当前版本 API，比较耗时、显存与数值行为；若使用 scaler，保存恢复其状态 |
| P3 Docker，约 2—3 次课 | 原生环境已跑通且有隔离需求 | 制作可追溯环境，核对宿主驱动兼容并复跑小任务；不以能写 Dockerfile 代替理解环境 |
| P4 DDP 或 compile，周期按兼容性评估 | 确有多卡／编译需求，单卡链路稳定 | 二选一先做最小实验，记录正确性、实际收益及兼容性；不保证一定加速 |
| P5 部署，约 2—4 周另排 | 研究训练能力已验收，确有部署或求职需求 | 先导出与核对输出，再按硬件选择 ONNX／TensorRT；量化和 FastAPI 继续按需增加 |
| P6 BAT 模块迁移，约 1—2 周另排 | ViT 和双模态接口已验收 | 核对原论文与实际源码，将融合组件写成自包含模块，接入已知基线，做公平对照；正确实现而无提升仍可通过工程验收 |

性能和部署报告写清硬件、输入形状、batch、精度、预热、测量边界和准确性协议。伪红外不能代替真实传感器证据；“工业级”“完整复现”等结论必须与实际交付范围对应。
